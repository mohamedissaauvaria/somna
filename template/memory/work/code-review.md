# Code review (example)

## What I check first
- Does the change do what the description says, and nothing else?
- Are new code paths covered by a test that would fail without the change?
- Are errors handled where they happen, with a message a user can act on?

## Conventions
- Small pull requests. Split refactors from behaviour changes.
- Names say what a thing is, not how it is built.
